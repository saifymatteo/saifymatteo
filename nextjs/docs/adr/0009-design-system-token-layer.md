# The design system is a token layer with a grammar, adapted from the Apple reference

The portfolio had a spec (exact Figma measurements in `design/SPEC.md`) but no system: every inconsistency in the codebase — 29 hardcoded `text-white`, six radius classes, six shadow variants, an `em`-based heading ladder that compounds with Tailwind's `text-*`, five font weights with no declared ladder — traced to that missing layer. We decided to build our own design system by **adapting** the Apple design analysis (an external reference document, not committed to this repository) rather than adopting it: Apple's structural discipline (semantic role tokens, four-role radius grammar, single-shadow policy, weight ladder 300/400/600/700, negative tracking at display sizes, 17px body, a Parchment alternate surface) sits on top of our identity — the brand gradient as a surface role plus the Gradient Bar as the one sanctioned divider, three typefaces (Fira Sans/Fira Code/Cookie), the visitor's Theme choice (ADR-0007), and our own `#2e2e2e` dark canvas. The token layer lives in `app/globals.css`: two layers (semantic roles as the only component-facing API over a raw palette kept for shader internals and gradient stops), with the legacy `primary-*`/`secondary-*` names kept as aliases pointing at the semantic tokens so adoption is a rename with byte-identical rendering (the ADR-0008 pattern). The grammar and component specs live in `design/DESIGN.md`, the single source of truth; `SPEC.md` is demoted to a historical record. Rollout is two phases: Phase 1 ships the token layer and docs with no component migration; Phase 2 migrates components onto the tokens and prunes the legacy names.

## Considered Options

- **Adopt Apple wholesale** (single blue, no gradient, system-ui/Inter, fixed light-dominant tiles): rejected — it erases the brand gradient that SPEC.md calls the entire color system, abandons three typefaces that carry identity, and conflicts with the Theme choice system (ADR-0007), which Apple's fixed-tile alternation cannot express.
- **Tokenize the current design without a reference** (name what exists, no structural change): rejected as Phase 1-only value — it would bless the drift (six shadows, six radii, five weights) as the system instead of correcting it.
- **Rename our accent token to avoid shadcn's `accent`** (shadcn uses `accent` for menu-hover background; ours is the brand interactive color): rejected — it breaks the ratified glossary term. Instead the bridge maps shadcn's `accent` onto our brand accent, so menu highlights render brand-blue with `on-accent` text.
- **Defer the shadcn token bridge to Phase 2**: rejected — Phase 1 would ship tokens that half-activate shadcn anyway (menus get accent hover with no readable foreground), i.e. a visual change without the fix.

## Consequences

Phase 1's three intentional visual deltas: light-theme ink corrects `#2e2e2e` → `#1a1a1a` (SPEC's value wins over the drifted code value — ratified explicitly), body copy settles at 17px (the old `p, a { 1.1em }` hack dies; the intent becomes the `text-body` role), and nav menu highlights become live brand-blue instead of the silent no-ops they were (shadcn primitives referenced undefined tokens). Phase 2 owns the component compliance pass: migrate 29 `text-white`, 18 `font-medium`, the radius outliers (`rounded-3xl`, `rounded-4xl`, `rounded-[20px]`), four chrome shadows, and then delete the legacy `primary-*`/`secondary-*` aliases — the aliases are a scaffold, not API.
