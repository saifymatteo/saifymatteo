# Contact CTAs are tracked with explicit GA4 events

Contact-page actions are measured with three custom GA4 events fired via `sendGAEvent` — `contact_click{method, location}`, `resume_view{location}`, `resume_download{location}` — where `method` is one of `email`/`linkedin`/`github`, and `location` is `contact_page` or `footer` (the two surfaces that expose the same CTAs). This was chosen over relying on GA4 Enhanced Measurement after an empirical audit (browser session against the live measurement ID watching `/g/collect` hits) showed the property sends `page_view` and `scroll` but **no** outbound-click events for LinkedIn/Github links — and structurally, EM could never cover the other half anyway: `mailto:` links are excluded from EM outbound tracking, the Resume dialog open is pure SPA state, and the dialog's Download href (`/api/resume`) carries no file extension, which EM's extension-based `file_download` detection requires. The footer's Résumé link (the raw GitHub-releases PDF URL) _would_ qualify for EM `file_download`, but mixing EM and manual sources for one funnel invites double-counting and Admin-toggle drift, so it is tracked manually too, as `resume_download{location: 'footer'}` — "resume download intent from any surface", with `location` separating the dialog's Download button from the footer link. Events fire on click intent (client-side), not delivery confirmation: `<a download>` gives no completion event, and server-side counting was declined as a separate pipeline. Event params never carry the email address (GA4 prohibits PII). Custom events don't appear in GA4's default reports — view them via Explorations or a custom report. Dev traffic intentionally reaches the property so local runs are verifiable; `localhost` is excluded from reports by an internal-traffic filter in GA4 Admin (an Admin-UI action, not code). GA4 Enhanced Measurement is left as-is (outbound clicks off/unreliable here) — the site's CTAs are all covered by explicit events, and re-enabling EM later would only add redundant auto events, not gaps. The `TrackedLink` client wrapper (`components/tracked_link.tsx`) exists because `page.tsx`/`footer.tsx` are server components; `resume_dialog.tsx` (already client) calls `sendGAEvent` directly.
