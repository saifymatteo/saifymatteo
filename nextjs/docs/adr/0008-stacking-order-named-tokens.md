# Stacking order is named in one place

The site's cross-file stacking contracts are named in `components/components.css` as four custom utilities — `z-backdrop: 0`, `z-content: 10`, `z-nav: 49`, `z-overlay: 50` — and call sites express intent (`z-nav`, `z-overlay`) instead of raw numbers. Two contracts exist: content-above-backdrop (`z-content` over `z-backdrop`, owned by `page_hero.tsx` — the stacking-context wrapper that motivates portaling full-screen dialogs to `document.body`) and nav-below-overlay (`z-overlay` over `z-nav` — the Resume dialog and image lightbox both sit on this tier). The values deliberately mirror the historical `z-0`/`z-10`/`z-49`/`z-50` they replace, so adoption is a rename with byte-identical rendering; changing a layer's height is now a one-place edit. Component-internal z-index (`home_hero`'s z-0/z-1 composition, controls inside the lightbox overlay) stays numeric — local layering within one stacking context is not a contract. A full z-scale token system was declined: two contracts don't warrant one, and the width half of the original friction was already solved (`content-max-width` utilities). Scroll-reveal stagger was reviewed and declined in the same pass — three call sites, no drift; an `index` prop on `Reveal` would trade visible arithmetic for speculative API.
