# Case-study Section invariants live in one module; raw sections are not public

Case-study Section interpretation — which sections render, and with what ordinal — lives in one pure module (`lib/projects/case_study.ts`) behind `lib/projects/projects.ts`, instead of being re-derived in the page component from a raw `caseStudy` array. The public `Project` type deliberately omits `caseStudy`: content files supply it via an internal `ProjectContent` type, and the only public access is `getCaseStudySections(project)`, which returns render-ready `SectionView`s (resolved `kind`, drop rules applied, contiguous position-derived ordinals). The two invariants from CONTEXT.md — media-less Preview sections are excluded, ordinals are derived from position and never authored — are therefore enforced in one tested place; previously they were enforced by string-matching the domain term `'Preview'` against `section.title` in two separate spots in `case_study.tsx` (numbering filter and render dispatch). Sections are discriminated by an explicit `kind: 'preview' | 'text'` field rather than the title string or structural inference from media presence: the title-based match coupled a data value to domain behavior, and "has media ≠ is a Preview" keeps media-less Previews, all-text case studies, and text sections with future media all representable. Featured Works selection (the first three projects by module order, static max) moved into the module as `getFeaturedProjects()` so the home page never changes when additional projects land. Consequence: the Section invariants have node-test coverage, a rule change (new section kind, numbering scheme) is a typed edit plus test in `lib/projects/`, and the page stops knowing `CaseStudySection` internals.
