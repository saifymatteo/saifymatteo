# Contact Submission rules in one isomorphic module

Contact Submission rules — the field schema, validation, and the shape of the resulting email — live in one isomorphic module (`lib/contact_submission.ts`) that both the Contact Form and the POST route import, instead of being split between the form's HTML attributes and private functions inside `app/api/send/route.ts`. The module is pure (no Node APIs, no fetch, no React) so it runs in both environments; secrets (`RESEND_API_KEY`, `TURNSTILE_SECRET`, `TURNSTILE_HOSTNAMES`) stay in environment variables, and the Human Check (Turnstile) and Resend integrations stay thin adapters inside the route. Rules are typed module constants rather than environment variables: client-shared values are compiled into the bundle regardless (env would require build-time `NEXT_PUBLIC_` inlining), production values live in Cloudflare rather than a repo `.env` (so env-based config is already two places by platform design), and constants get tsc + test coverage instead of runtime string parsing. The API contract stays byte-identical (`{ok:false}` binary responses; field-level errors were considered and deliberately deferred). Consequence: adding or changing a submission rule is a typed, testable edit in one file, the form enforces the real limits while the visitor types, and the route thins to parse → validate → Human Check → send.
