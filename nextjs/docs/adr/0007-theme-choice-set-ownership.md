# The Theme choice set is the cycle order and lives with the state

The Theme choice set — its order, its labels, and the cycle derived from them — lives in `lib/theme.ts` alongside the Theme state, instead of being re-declared in the navigation bar. `THEME_CHOICES` (typed `as const satisfies readonly ThemeChoice[]`) is the single ordered source: `nextChoice` derives by index arithmetic rather than a hand-written switch, and `THEME_CHOICE_LABEL` provides the human-facing labels consumed by both the mobile menu's visible text and the toggle's aria-label. The menubar keeps only what is inherently UI — the icon mapping (`Record<ThemeChoice, LucideIcon>`, exhaustive-checked by tsc, so a new choice forces the icon decision at compile time) and presentation copy. Previously the navigation bar re-declared the array, the labels and the icons while `lib/theme.ts` separately owned the union and a switch whose order had to agree with the array by discipline; a fourth choice would touch two files with no mechanism connecting them. Consequence: adding a choice is one line in the array plus one label in `lib/theme.ts`, one compiler-forced icon decision, and `[data-theme]` tokens in `app/globals.css` (styling, legitimately separate) — while cycle order, labels and menus cannot drift, asserted by coherence tests in `tests/theme.test.ts`.
